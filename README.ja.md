[AIの入口](SKILL.md)／[作例一覧](gallery/index.html)／[検証記録](VERIFICATION.md)／[English](README.md)

## 3.4の重点改修

実際の制作で見つかった失敗を、制作指示だけでなく検査にも反映しました。

- CSSの閉じ忘れをビルド・QAで検出。実際の配色、見えない棒、画像の切り取り、文字の重なりも診断します。
- 原典表の版・行・列・単位・評価条件を対応づけて検査し、異なる比較条件の混在を防ぎます。
- 最後に作った配布HTMLとQA結果のハッシュを照合。後から変更されたHTMLや読込素材、未完了の検査を検出します。
- 論文やWikiを読者に伝わる順序へ組み直す手順、図の実際の関係、操作後の説明、元画像と切り取りの確認を具体化しました。
- 画像が見られない状態を目視済みとは扱わず、失敗した取得要求の無限リトライも避けます。

機械で判定できる問題・要確認・未測定を区別し、デザインの一律な禁止事項は増やしません。
[検査の範囲](references/verification-and-delivery.md)と[実施した検証](VERIFICATION.md)を参照してください。
新しいSKILLSで各外部モデルに再制作させた結果は、まだ測定していません。

## 3.3から引き継いだ改修

**文章、情報密度、図の意味、PDFの実際の書体を、別々に確認する版です。**
見出しが流暢でも計算が違う、条件分岐を一本道に描く、提案を約束のように
書く、といった失敗を、制作順序・コード・回帰テストへ反映しています。

「短く、白く、無装飾に」を一律に要求しません。必要な条件表・詳細は残し、
発表用と自読・参照用を区別します。詩的な表現やブランドらしい声も、役割が
あれば使えます。余白率・文字数・禁止語だけで良し悪しを決めません。

3.3で追加した、**12組の修正前／修正後（24ページ）**、3ページの測定説明、
期間に応じて順位と見出しも変わる操作例を収録し、作例は計295ページです。
図104・動き64・操作24・全体構成36という既存ライブラリーも維持しています。
新規作例のデータは架空で、利用者の原稿・企業情報・ログを転載していません。

[文章の編集](references/writing-and-editing.md)／[密度と構成](references/writing-and-editing.md)／
[数値と図の意味](references/evidence-and-diagrams.md)／[PDFの書体](references/verification-and-delivery.md)

PDFは印刷状態を作ってから再度フォントを待ち、実際に描画された書体を確認します。
納品時はプロジェクトの `fonts.json` と照合し、ページ数・文字回収も検査します。
失敗時は既存の納品PDFを上書きしません。フォント自体の自動配布はしません。

新しいQAの `automatedChecksPassed` は描画・検査の結果です。
`deliveryApproved: false` と残る確認項目を併記し、自動検査を文章・デザインの
合格と読み替えないようにしています。これは完成を永遠に拒むためではなく、
目視・内容・操作・書き出しの確認を区別するためです。

回帰テストは実装の
失敗防止を検証するもので、どのモデルでも同じ文章や美しさになる保証ではありません。

## 3.2で重点的に改善したこと

**文章と制作メモを分離します。** 主張・根拠・条件は聴衆に見せ、操作するタイミングや
制作上の指示はノートや運用手順へ分けます。明確な制作指示・プレースホルダーは
納品用ビルドで検出し、スクリプト実行後の画面でも再検査します。禁止語の置き換え
ではなく、見出し・本文・注釈が何を伝えるかを整えるための手順を追加しました。

**余白を、埋める面積ではなく関係として扱います。** 主役の領域、実際の文字量、SVGの
描画範囲、注釈との距離、読順から構図を作ります。広い空白、孤立した最終行、小さすぎる
図などを診断しますが、装飾を足して数値を稼ぐことは勧めません。白紙から図を組み立てる
例と、違和感の原因別に直す[修正ガイド](references/repair.md)を収録しています。

**マウスとキーボードの動作をそろえました。** 「次へ」をクリックした後に右矢印が
効かなくなる問題を修正し、入力欄・スライダー・IMEのキー操作は保護します。実際の
キー入力、アニメーション途中、戻る、連続入力、再訪問、静止出力を試験しています。

**自社テンプレート化に対応しました。** PPTXから配色・書体・形状配置を観察して
ブランド規則の案を作り、HTML用の柔軟なブランド設定や、6種類の名前付きレイアウトを
持つ実際のPOTXを作成します。抽出結果は自動承認しません。社内資料・ロゴ・規則は
利用者のプロジェクト内に保管し、公開Skillには混ぜません。

## 導入と最初の依頼

`slide-studio`フォルダーを丸ごと、使用するAIエージェントが対応するskills
ディレクトリへ配置してください。`SKILL.md`だけをコピーすると実装や参照文書が
欠けます。[導入ガイド](references/working-agreements.md)にホスト別の扱いを記載しています。

> slide-studioを使って、添付資料から研究発表を作ってください。
> 聴衆は分野の基礎を知っています。構成・デザインは判断し、主張・根拠・限界を区別してください。
> 発表者向け指示を本文に混ぜず、画像や図の読みやすさ、余白、キーボード操作も確認してください。
> HTML、静止PDF、編集ソースを納品してください。

作例一覧は、展開後の `gallery/index.html` をブラウザーで開くだけで見られます。
HTMLビルドにはNode.js、描画検査とPDF出力にはPython・Playwright/Chromiumなどが必要です。
インストールと具体的なコマンドは[英語README](README.md)にあります。

## 自社テンプレート化

```sh
python scripts/brand-capture.py reference.pptx --out private-brand
node scripts/brand.mjs proof private-brand/brand.json --out private-brand/proof.html --allow-draft
# 実物と抽出結果を照合し、承認された規則だけを確定する。
python scripts/brand-template.py private-brand/brand.json --out company-template.potx
```

既存スライドの本文・ノート・画像・元ファイル名は既定でコピーしません。
ただし、任意の複雑な既存マスターを完全再現する機能ではありません。
固定テンプレートと、内容に合わせて自由に構成するブランド規則を使い分けます。
詳細は[ブランドガイド](references/brand.md)へ。架空の設定による[実際のPOTX](assets/brands/example.potx)も同梱しています。

## 検証画像を溜めない

既定では個別PNGを保存せず、画像を埋め込んだレビューHTML・検査JSON・管理ファイルの
3ファイルにまとめます。同じ検証先を再利用し、変更済みファイルや管理対象外のファイルを
保護します。問題画像だけを上限付きで保存する指定も可能です。

ノートは通常のHTMLソースに含まれます。非公開機能ではありません。
配布用は `craft.mjs build ... --strip-notes` でノートなしのHTMLを作れます。
その後、実際の配布用HTMLをQAにかけてから最終照合します。

```sh
python scripts/verify-review.py presentation/public.html --report presentation/.studio-review/final/report.json
```

この照合の成功は「そのファイルの自動検査結果が一致した」という意味です。
文章・図の意味・見た目の承認ではなく、操作の全選択肢も別途確認します。

## 更新時の注意

自分の資料・ブランド設定をバックアップし、インストール済みSkillを差し替えてください。
**すでに作ったHTMLには古いプレイヤーが埋め込まれています。キーボード修正を反映するには、
新しいSkillでソースからHTMLを再ビルドする必要があります。**

PDFの書体を直すには、書体を確認してから再出力が必要です。過去の成果物を新しい検査で
調べることはできますが、それだけで内容は修正されません。

作例から取り出したものは下書きです。実際の題名・本文・図のラベル・根拠へ置き換えてから
完成扱いにしてください。検査を通すためだけにワークショップモードへ変えてはいけません。

## 範囲とライセンス

独自コード・文章・図はMITライセンスです。既存写真の権利情報は別途記載しています。
フォントファイル、認証情報、特定ユーザーの個人情報や業務資料は同梱していません。
公開用Skillと、利用者の社内ブランドキットは分離します。

OBJ/STLはメッシュの表示で、STEPを編集するCADではありません。PDFとPPTXは静止出力で、
HTMLの操作・動画再生・アニメーションを引き継ぎません。画像型PPTXと、対応する文字や
形状を編集できるPPTXは別の経路です。

外部AIモデルでの制作性能比較や、Microsoft PowerPoint・Keynoteの実機確認は未実施です。
同梱テストはソフトウェアの振る舞いと描画を確認するもので、美的品質や全モデル同等の
制作能力を保証しません。実施した検証と制限は[検証記録](VERIFICATION.md)にまとめています。
